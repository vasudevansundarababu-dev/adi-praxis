# 3. Program Manager (PM)

A PM runs projects: creates them from a published template, publishes the opportunity page, gets experts selected and
assigned, follows progress, opens requisitions for partners and the careers page, and confirms the weekly pay run.
A PM sees only the projects they own.

Your Home page shows **New project →** and tiles for "Projects staffing", "Projects in progress" and "Pay runs waiting
for you".

## 3.1 Create a project

1. **Projects → Projects** → **New project** (or **New project →** on Home).
2. Work through six steps. **Save as draft** keeps your work at any step; **Back** and **Next** move between steps.

| Step | What you fill |
| --- | --- |
| **1. Template** | **Domain and workflow \*** (only published templates). You see its Primary work, Verification / reward and Human gate |
| **2. Basics** | **Project name \***, Description, **Start date \***, **Target end date \*** |
| **3. Volume, diversity and TPT** | **Task mode \***: "Authoring (experts write new tasks)" or "Annotation (workers process inputs)". Authoring: **Distinct-task target \***, **Max tasks per expert \***. Annotation: **Number of tasks \***. **TPT (minutes per task) \*** ("A planning and pay target, not a deadline"), Hours per worker per day. **Coverage quotas** come from the template; you can raise but not lower them |
| **4. Demographics** | At least one filter. **+ Add filter**, then Required (must match) or Preferred (raises the match score) |
| **5. Job description** | Use an existing one, or create one: **Title \***, **Required skills \***, **Responsibilities \***, **Wage per task \***, **Currency \***, **Location type \*** → **Create job description** |
| **6. Review and submit** | Check the summary → **Submit project** |

The **Estimates** panel shows required authors and coverage slots, total effort, working days (Monday to Friday),
required workers and labour budget (tasks × wage per task).

If something is missing you see "This project can't be submitted yet." and a list. After submitting, the project is
**Ready for staffing** and its job description, demographics and template version are frozen.

## 3.2 Assign Validators

On the project page, in **Validators**, choose **Add reviewer \*** and select **Add**. Validators decide the
applications for this project's pool. With none assigned you see "No reviewer assigned yet; only Admins can decide
applications."

## 3.3 Publish the opportunity page

The opportunity page is what candidates read before applying.

1. On the project page select **Opportunity page**.
2. Optionally **Import a JD document** (PDF or Word, up to 10 MB). Check the extracted text and select **Confirm text**
   (or **Discard**); it is added to the full description.
3. Fill the brief: **Title \***, **Domain \***, **Specialty \***, jurisdictions, languages, compensation (leave blank if
   not approved), **Contribution roles \***, **Summary \***, **What we will ask \***, **What not to disclose \***, and
   the optional sections.
4. **Eligibility criteria \***: each has an id, the criterion, Required or Preferred, and the evidence expected. Only
   task-related criteria approved by a domain owner; the assistant never adds any.
5. **Questions candidates will be asked** are generated from the brief and criteria. You can edit them or **Reset to the
   generated questions**.
6. **Save draft**, then **Save and publish** ("Published. Candidates now see this version."). **View public page**
   opens it in the candidate app. **Close to new applications** stops new applicants.

## 3.4 Staff the project

1. On the project page select **Start staffing**. This opens **Resource assignment** and runs the first match.
2. To find candidates, **Launch sourcing campaign** (the opportunity must be published). Use **Copy post text** and post
   it on LinkedIn manually. The panel counts Clicks, Applies, Identity done, Approved and Assigned. **Pause**,
   **Resume** or **Close campaign** when needed.
3. Candidates apply, a Validator selects them, and they finish onboarding. Then they appear in the table with a match
   score. Select a score to see the breakdown (skills, experience, language, availability, preferred filters).
4. Assign experts:
   - **Assign** on one row, **Assign selected (n)** for ticked rows, or **Assign top N**.
   - Each assignment sends a **proposal**. The expert has 7 days to accept. Only accepted experts count.
   - **Withdraw proposal**, **Release** an accepted expert, or **Reject** a candidate for this project only.
5. The cards show Required workers, Accepted, Awaiting reply and Shortfall. **Re-run match** after changes. When full:
   "This project is fully staffed."

## 3.5 Follow progress and manage tasks

- **Progress dashboard**: distinct accepted tasks, distinct authors, in review, rework rate, active time vs TPT, the
  coverage matrix (empty / in progress / filled), edge cases, duplicates, and tasks per expert. It refreshes every 15
  seconds and says "Complete" when the target and all required coverage are met.
- **Tasks and invites**:
  - Filter tasks by status. **Reclaim…** a stalled task (reason: Stalled, Expert unavailable, Other) to return its slot
    to the queue. TPT never expires a task.
  - Each accepted expert gets a single-use invite link that lasts 7 days. **Resend** (revokes the old link) or
    **Revoke**.
  - Annotation projects: **Add task inputs** from a CSV or JSON file. If any row fails validation, nothing is added.
- **Pause project** (experts keep their saved work), **Resume project**, or **Cancel project** (final).

## 3.6 Requisitions (SME supply)

A requisition asks partners and the careers page for people at one tier.

1. **Projects → Requisitions** → **New requisition**.
2. Choose your **Project \***. If needed, select **Switch on SME supply for this project** (this does not change JD
   matching).
3. Fill **Title \***, summary, **Domain \***, **Tier \*** (Expert, Reviewer, Annotator), **Headcount \***, dates,
   hours, location, jurisdictions, languages.
4. **Minimum requirements**: minimum years, licence required, qualifications, notes. The screen only recommends; a
   Validator confirms any "not met".
5. **Channels and pay**: tick **Partners allowed to submit**; tick "Also accept direct applications from the careers
   page"; set a deadline and "Most candidates per partner"; choose who pays the SMEs:
   - **Direct**: Praxis pays each SME from the rate card.
   - **Via partner**: the partner pays its people; Praxis records no earnings.
6. **Create draft requisition**.
7. On the requisition page:
   - **Guidelines** → choose the package and version → **Link guidelines**.
   - **Rate card** (direct pay only) → choose the version → **Link rate card**. Without one, SMEs earn nothing.
   - **Change state** → **Open**. Allowed partners are told and can submit. Later: **Pause**, **Mark filled**, or
     **Close…** (final).
8. **Submissions** lists every candidate with source (partner or careers page), requirement screen and state. Editing
   an open requisition tells every allowed partner.

## 3.7 Confirm the weekly pay run

1. **Payments → Pay runs**. If this week's run does not exist, select **Build pay run** (blank week = last week).
2. Open the run, check **Payments**, **Held** and **Carried forward**, and select **Confirm pay run**.
3. Finance then approves and submits it ([Finance chapter](05-finance.md)). You can also view **Rate cards**.
