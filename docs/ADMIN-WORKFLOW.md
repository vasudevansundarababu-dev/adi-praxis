# Admin workflow policy

The user-requested Admin workflow policy supersedes older SPEC/SME-SUPPLY instructions that require multiple internal roles or people for workflow sign-offs. Admin is sufficient for operating Praxis; PM, Reviewer and Finance roles and existing assignments remain readable for compatibility and are not silently reassigned or deleted.

- Admin can create, prepare, staff and operate projects without an additional PM role. Project reviewer delegation is optional for legacy accounts and is hidden in the Admin project summary.
- Admin can accept submitted tasks without a separate Reviewer assignment, including tasks authored through their own candidate identity. Declared conflicts must still be resolved. Contract validation, revision checks, data/duplicate checks, checklist answers, append-only dataset records and the identity of the actual decision maker remain intact.
- Every certification item family, including Expert tier, needs only the Admin decision after valid samples. One Admin grade finalizes written answers, including existing pending two-person reviews and domains with certified Experts. Previous real confirmations are preserved; no other-role approval is synthesized. Courses, blueprints, licence and certification decisions remain explicit Admin actions.
- Admin can release draft or confirmed pay runs directly via `POST /pay-runs/:id/release`. This replaces PM confirmation and Finance sign-offs with one audited `pay_run.admin_released` action, preserves historical approval/confirmation fields, and sends no money. Admin submits separately. A recipient cannot release their own run; payee eligibility, holds, provider idempotency and tenant checks remain enforced. Legacy Finance workflows remain compatible.
- New-user UI defaults to Admin and offers only Admin. Existing role history is preserved; this policy does not promote existing non-Admin users.
- Synthetic software examples are already created/downloaded directly by Admin without workflow review. They remain draft fixtures, not fabricated human acceptance or rights clearance. Dataset exports record actual Admin acceptance.

Authentication, tenant isolation, project ownership for legacy non-Admin accounts, candidate and partner audience separation, audit history and append-only hash chains are unchanged. There is no blanket Admin override in the RBAC middleware. No automatic backfill, migration, money transfer, model call, rights clearance or Anvil approval is performed by this policy change. Anvil remains a separate system with its own controls.
